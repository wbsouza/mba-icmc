\subsection{Strategy configuration as a controlled variable} \label{subsec:strategy-config}

Section~\ref{subsec:deterministic-execution} commits every parameter of every filter to the strategy's configuration file rather than to code. The implementation realizes this as one YAML descriptor per strategy, \path{strategies/<name>/config.yaml}, with one section per configurable filter: \path{price_features} (the EMA, RSI and MACD periods shared by training and serving), \path{indicator} (F2), \path{pattern} (F3), \path{news_context} (F4), \path{risk_guard} (F5), \path{capital_mgmt} (F6) and \path{meta_learner} (F7, holding $\theta_{\text{high}}$, $\theta_{\text{low}}$, the regime-gate switch $g$ and the label horizon). Each filter parses and validates its own section; a filter listed without its section, a section without its filter, a missing key or an out-of-range value stops the run before the first bar. Variants are expressed through \path{extends:} chains of any depth, which compose like override files: the hybrid descriptor inherits the F5, F6 and F7 sections from the baseline and adds only \path{news_context}, so both variants face identical execution assumptions by construction. Sections with defaults may be omitted, and the loader writes the effective values back so that the \path{strategy-config.json} saved with every run shows exactly what was used. The command \path{algo-backtest explain-strategy} prints the resolved configuration together with the origin of every value (the descriptor that set it, or the default), and the same provenance is written per run as \path{strategy-provenance.json}. The provenance file was added after the September replays reported below; those runs carry the resolved \path{strategy-config.json} only.

This mechanism is what makes a configuration diff the unit of experimental manipulation. The ablations of Section~\ref{subsec:strategy-variants} will vary one parameter, or one filter, per variant descriptor while everything else is inherited unchanged, and the saved provenance makes the manipulated value auditable from the run directory. Table~\ref{tab:pilot-parameters} lists the values resolved for the September replays. The two run parameters, \path{size} and \path{cash}, are the only values passed on the command line. The F6 section computes a risk-based lot from \path{risk_per_trade} and the fixed stop distance, but the chain strategies size their orders from the \path{size} parameter as a fraction of equity held as notional; the risk-based lot is computed, not applied. The consequences are discussed with the results.

\subsection{First replay round and zero-trade diagnosis} \label{subsec:zero-trade}

The first September replays ran with the gate $g$ on, the form of the terminal rule that requires the trend regime to agree with the direction the probability points to. Both completed successfully and closed zero trades. The baseline run is \path{baseline/20260927T044836-4cd12c922200}, and the hybrid run is \path{hybrid/20260927T053156-4f2ebf081eaf}. The UTC identifiers fall on September 27 although execution occurred on September 26 in the operator's Pacific timezone. They remain on disk as the audit trail of this round. A zero-trade replay requires investigation of coverage, model outputs, and filter vetoes before interpretation, and its zero-valued summary statistics are neither evidence of efficacy nor a validated null result.

Data was not the cause. At training time the canonical GDELT months from February through August 2015 were complete, with their completion markers written and every calendar day present, and both model artifacts hash all seven months. The September replay evaluated 31,512 minute bars, every filter ran, and the decision table records a combiner probability $\hat{p}_t$ for 23,367 bars. The remaining 8,145 bars never reached F7: they were vetoed by F1 on a conflict between the primary and the higher-timeframe trend direction.

The cause is a sign disagreement between the fitted combiner and the gated rule. With $g$ on, BUY requires $\hat{p}_t > 0.55$ together with a bull regime, and SELL requires $\hat{p}_t < 0.45$ together with a bear regime. In September the combiner produced $\hat{p}_t < 0.50$ on every one of the 11,540 bull bars (99th percentile 0.493) and $\hat{p}_t > 0.49$ on every one of the 11,827 bear bars (1st percentile 0.491). Neither conjunction can hold, so all 23,367 bars resolved to HOLD. The bars that would have fired without the gate were 3,222 bull bars with $\hat{p}_t < 0.45$ and 1,976 bear bars with $\hat{p}_t > 0.55$ for the baseline, and 3,671 and 1,780 for the hybrid. The label is the fifteen-minute forward up-move of Section~\ref{subsec:late-fusion}; at that horizon the model has learned mean reversion relative to the EMA trend regime, which the trend-following form of the rule forbids. Retraining on the same six months reproduces the pattern, so the block is the rule-model interaction, not the data. The calibration data of Section~\ref{subsec:threshold-calibration} show the same anti-alignment on the July validation span (mean $\hat{p}_t$ of 0.475 on bull bars and 0.525 on bear bars), so the conflict was detectable before September was inspected; it was, however, detected after.

The decision to switch the gate off was taken after inspecting these September outcomes. By the rule stated in Section~\ref{subsec:workflow-stages}, a pilot outcome that guides subsequent model or rule selection turns that window into development data. September 2015 is therefore development data for the gate decision and cannot later be presented as an untouched test set for it. The gate remains available as a switch; a later untouched window is required before any statement about the ungated rule counts as confirmation.

\subsection{Machinery verification} \label{subsec:machinery-verification}

Before the second replay round was interpreted, a written QA procedure (\path{evidence/qa-procedure.md} in the story record) was executed by hand and then by a deterministic check script over both run folders. The procedure verifies that the amended chain produces BUY and SELL decisions that become LEAN trades, that the account starts from the requested deposit, and that every parameter the run used is auditable from its artifacts: the resolved \path{strategy-config.json} must show the gate off and the thresholds of Table~\ref{tab:pilot-parameters}, the log must record the starting cash and both decision types, \path{trades.json} must be non-empty, the engine's equity series must not be flat, and the decision table must contain BUY and SELL rows joined to a trade identifier. The check script passed on both September runs. It also found one defect: the resolved configuration file, written inside the LEAN container by the atomic-write helper, came out owned by root with mode 0600 and was unreadable on the host, so the run's parameters could not be audited from outside the container. The helper in \path{algo_core.atomicio} was corrected so that the published file receives the ordinary umask mode, with a BDD scenario covering the case, and the two affected run folders were made readable with an unprivileged container. The procedure judges the machinery only; it does not read the numbers as a strategy result.

Artifacts of the first round are kept in the directory \path{2026-09-26-six-month-pilot/} beneath the local \path{algo-suite/data/training/} root, and those of the second round in \path{2026-09-27-f7-ungated-september/}, which links the same data root and the same frozen models and records the model hashes and the code revision at launch. \subsection{Execution model for the confirmation reruns} \label{subsec:execution-model}

The execution caveats of Sections~\ref{sec:baseline-results} and~\ref{sec:hybrid-results} are removed by the execution-realism story, which turns the F6 section of the strategy descriptor into an actual trade plan and adds a top-level \path{execution} section for fill costs. Every value below is a YAML key with recorded provenance; none is a code constant. The plan follows the reference strategy of the reference FX manager described in Section~\ref{sec:execution-engine}. Relative to the pilot of Table~\ref{tab:pilot-parameters}, the reruns change the following, and only the following.

\begin{itemize}
    \item \textbf{Account.} The starting deposit stays at \$10,000 through the \path{cash} run parameter. The \path{size} parameter no longer exists for the chain strategies; every order is sized from the F6 plan.
    \item \textbf{Stop first.} The base stop distance comes from \path{stop_distance_source}, which may be \path{fixed} (\path{stop_loss_pips}), \path{atr} (\path{atr_multiplier} times the bar's ATR over \path{price_features.atr_period}) or \path{swing} (the distance to the rolling swing low or high over \path{price_features.swing_lookback_bars}); the bundled descriptors select \path{swing}. The base distance is shrunk toward entry by \path{stop_loss_shrink} of 0.20 and floored at the larger of \path{min_stop_pips} (5) and \path{min_stop_factor} of 1.2 times the declared \path{broker_stop_level_pips}.
    \item \textbf{Lot from risk.} The lot follows from \path{risk_per_trade} of 0.03 and the stop distance, through \path{pip_value_per_lot} (\$10) and \path{lot_notional_units} (100,000). The lot that the pilot computed and ignored is now the quantity actually ordered.
    \item \textbf{Targets and trailing stop.} \path{targets} holds one level at 2.0 times the stop distance closing 0.5 of the position; the remainder rides the trailing stop. \path{trail_stops} holds one step: once price has moved 0.5 of the stop distance in the trade's favor, the stop moves to $-0.66$ times the stop distance from entry. A signal whose first-target reward-to-risk ratio falls below \path{min_reward_risk} of 2.0 is vetoed by F6 before entry.
    \item \textbf{Concurrency.} \path{max_concurrent_trades_per_account} in the F5 section is lowered from 5 to 2, the reference plan's limit.
    \item \textbf{Fill costs.} \path{spread_pips} of 1.0 is charged as half-spread slippage on every fill, on top of the quote bars; \path{commission_per_lot} is 0.0 for the reference broker and stays a declared parameter. The pilot's effective cost was the 0.3-pip median spread of the quote bars alone.
    \item \textbf{Exits.} Entries are market orders; the stop is a stop-market order and each target a limit order, placed together with the entry and paired so that the fill of one cancels the other. \path{close_on_veto} is false: a later filter veto leaves an open position to its stop, targets, trailing stop and \path{min_hold_bars} (0), so the planned exits govern the trade. In the pilot, by contrast, positions were opened and closed solely by per-bar chain decisions.
\end{itemize}

The hybrid descriptor inherits the whole F5, F6 and \path{execution} sections from the baseline and adds only its F4 section, so both variants face identical execution assumptions by construction. The resolved values are written to every run's \path{strategy-config.json} and the plan of each entry to \path{trade-plans.json}. The September--November 2015 reruns under this model use the frozen September-26 six-month models and are the pilot check of the execution machinery, not the experiment; they are reported in Section~\ref{sec:confirmation-results}.

\section{Data Coverage} \label{sec:coverage-results}

The baseline closed 1,032 trades and ended the month essentially flat, at $-0.05\%$ with a maximum drawdown of 1.5\% and a win rate of 60\%. A flat or negative result for an unleveraged single-pair price-only strategy is the expected level rather than a failure; the quantity that bears on H1 is the paired difference against the hybrid, not this absolute level. The result is nevertheless not an economic one, for reasons visible in the trade ledger rather than in the summary statistics.

\begin{itemize}
    \item \textbf{Transaction costs are nearly absent.} The only cost is the bid-ask spread embedded in the Dukascopy quote bars materialized for LEAN, whose median over the September minute bars is 0.3 pip. Every trade in \path{trades.json} carries zero fees; no commission, slippage or financing cost is modeled.
    \item \textbf{No protective orders were placed.} The fixed 20-pip stop of Table~\ref{tab:pilot-parameters} is recorded in the sizing context but no stop-loss or take-profit order is submitted to the engine (technical-debt item TD-46). Positions are entered and exited only by the chain's per-bar decisions.
    \item \textbf{Position size is a fixed fraction of equity, not the risk-based lot.} Each trade holds half the account equity as notional, about 4,440 units of EUR/USD, because the \path{size} run parameter governs sizing; the 3\% risk-per-trade lot that F6 computes from the fixed stop is not applied.
    \item \textbf{The strategy flips at minute scale.} The median holding time is nine minutes, and the month contains about one thousand round trips per strategy. From the ledger, the average winning trade returns about 0.015\% of the starting deposit and the average losing trade about 0.023\%, which the progress record rounds to roughly 0.01\% and 0.02\%. A win rate near 60\% with that payoff ratio nets to approximately zero, and any realistic commission or slippage would dominate the outcome.
\end{itemize}

The machinery is proven: decisions become trades, the deposit is honored, and every parameter is auditable. The economics are not: the execution assumptions above make the equity path uninformative about what the same decisions would have earned under realistic costs and sizing. The zero-trade identifiers of the first round remain the historical record of this strategy's initial replay; the remark in the earlier snapshot that flat equity made variance and paired uncertainty unavailable is superseded, since both runs now carry a non-flat daily equity series, but no inference has been computed from it.

Under the execution model of Section~\ref{subsec:execution-model}, the same frozen models lose more than half of the deposit in every month replayed (Table~\ref{tab:confirmation-2015}). The two contracts are separate experiments on reused historical data; their difference cannot isolate a single execution parameter's effect, and the sweeps of Section~\ref{sec:ablations} were run to separate them.

\section{Hybrid Strategy} \label{sec:hybrid-results}

The hybrid closed 1,069 trades and ended at $+0.51\%$, with the same 1.5\% maximum drawdown and a 62\% win rate (Table~\ref{tab:september-replay}). Its decision profile differs from the baseline in 196 fewer BUY and 449 more SELL decisions over the same 23,367 bars that reached F7, with an identical F1 veto count because F1 is upstream of any news input. The news-context filter F4 abstained on all 23,367 hybrid bars: there is no sentiment source in this pilot, and no GDELT event-intensity veto fired in September. The hybrid's difference from the baseline therefore comes only from the news family's input to the combiner, not from the event gate. This is a narrower construct than the joint effect described in Section~\ref{subsec:workflow-stages}, and it is narrower still than the sentiment-augmented hybrid the research design proposes.

The execution caveats listed for the baseline apply unchanged to the hybrid, which inherits the F5, F6 and F7 sections and the two run parameters. The observed difference of about \$56 on a \$10,000 account over roughly one thousand near-zero-cost minute-scale trades is not interpreted here. No paired inference has been run: the stationary-bootstrap and deflated-Sharpe procedures of Section~\ref{subsec:rule-significance} require the daily equity series, documented cost treatment, the actual selection history (which now includes the gate decision and the threshold grid of Table~\ref{tab:threshold-calibration}) and pre-registered block settings, none of which has been assembled for these runs. A difference in a development window, under unrealistic execution, is not evidence for or against H1.

Under the execution model, both hybrid replays of each month lose more than half the starting account value, as Table~\ref{tab:confirmation-2015} shows. The baseline--hybrid ordering changes between September, October and November. Neither ordering supports a news-effect claim without paired inference, audited costs, and the full exploratory selection history.

\subsection{Tuning sweeps: candlesticks, quote activity, thresholds, plans and timeframes} \label{subsec:tuning-sweeps}

\subsection{News-only strategy (registered before its outcome)} \label{subsec:news-only}

A third experiment was registered on September 28, 2026, before any of its cells was run: a chain in which the news signal alone decides direction and the risk guard and money management govern the trade, with no price filter in the loop (\path{f4\_news\_context}, \path{f5\_risk\_guard}, \path{f6\_capital\_mgmt}, \path{f7\_meta\_learner}; F7 fitted on the news family only, that is on the GDELT event-intensity feature, the lexicon sentiment half remaining empty). It uses the Heikin-Ashi H4 money-management template, the one-year splits (fit March 2--December 31, 2015; combiner calibrated on January 2016; February 2016 held out), the H1 and H4 clocks, and thresholds 0.55/0.45 or, if the January validation band cannot reach them, symmetric 5\,\% and 10\,\% quantiles of that band, decided from the calibration file alone. A rule-only arm was added to the registration before any cell ran: F4 alone decides direction from the event-intensity reading (buy at or above the January-2016 90\,\% quantile, sell at or below the 10\,\% quantile, veto at $-0.5$), with no meta-learner and the chain terminating on F4; both sign conventions are registered as cells, since the mapping from cooperation and conflict to the EUR/USD direction is not known a priori. Each cell is one \$10,000 account from March 1 to December 31, 2016; March--October is ranked first and November and December are read last. The pre-declared primary comparison is news-only against the price-only baseline at H1 on the two untouched months, with the hybrid as the third arm; ten cells in all. The story record (\path{docs/stories/done/14-news-only-strategy/spec.md}) holds the registration.

The six news-only cells have run (evidence \path{news-only-cells-20260928T0545Z.md}). The news-family models are almost constant: their combiner probability spans 0.5253--0.5288 on the January validation bars at H1 and 0.5245--0.5265 at H4, so the registered thresholds fire on nothing (two cells with zero trades) and the quantile cells trade on noise: at H1, 209 and 230 trades with win rates of 28 and 27\,\% lose 42.6 and 38.5\,\% by December (maximum drawdown 51 and 47\,\%); at H4, 74 and 75 trades lose 22.1 and 14.4\,\%. In the untouched months the H1 cells lose 10 to 12\,\% in November and gain 7.6\,\% in December, the H4 cells gain 4.6 and 12.2\,\% in November and lose 2\,\% in December; no cell is positive in both. Against the comparators on the same clock and splits (price-only H1 $+2.5\,\%$ on 39 trades, hybrid H1 $+9.1\,\%$ on 37 trades over the same ten months), the news signal alone carries no directional information that the money-management template can monetize: one daily event-intensity scalar, repeated across the day's bars, cannot separate up from down at an hourly horizon. This is the direct answer to the thesis question in its strongest form for the data at hand, and it is negative. The rule-only arm has also run (evidence \path{news-cells-20260928T0600Z.md}). With the registered sign, higher cooperation intensity buying the euro, the rule loses at both clocks ($-47.0\,\%$ on 178 trades at H1, $-19.8\,\%$ on 48 trades at H4) and in both untouched months. With the opposite sign it is, in practice, a short-only rule, because the January 10\,\% quantile of intensity ($-0.0046$) was never reached in 2016 and no buy fired: at H1 it closes 39 trades, all short, for $+12.9\,\%$ over the ten months with a 15\,\% maximum drawdown, and it is positive in both untouched months ($+5.2\,\%$ in November, $+1.0\,\%$ in December); at H4, ten trades, $+3.1\,\%$, likewise positive in both. This is the first configuration in the study to pass the untouched-month check, and it must be read against the pair: EUR/USD fell 3.4\,\% from March to December 2016 and 3.5\,\% in November alone, so a short-only rule with a wide-target plan captured drift that a short-and-hold position would have captured too ($+3.5\,\%$ over the span). Whether the rule adds anything beyond direction-of-drift requires a matched short-only control (random short entries with the same plan and frequency) and a window in which the euro rises; neither was registered here, and the two sign cells were declared precisely because the sign was not known in advance. The result is therefore reported as a positive exploratory reading with a known confound, not as evidence for the news signal. The registered paired inference of Section~\ref{subsec:rule-significance} was then computed with block lengths declared before viewing (primary 4 and sensitivity 2 on the untouched months, 5 and 3 on the full span; 999 null-centred stationary-bootstrap resamples, seed 42; evidence \path{paired-inference-20260928T0615Z.md}). For the pre-declared primary comparison, news-only against the price-only baseline at H1, the mean daily difference on November--December is $+0.001\,\%$ with a 95\,\% interval of $[-0.34, +0.34]$ percentage points ($p = 0.996$), and $-0.16\,\%$ per day on the full span ($p = 0.18$); the null is not rejected. For the short-only rule against the same baseline the untouched-month difference is $+0.18\,\%$ per day with an interval of $[-0.13, +0.50]$ ($p = 0.24$), and $+0.03\,\%$ per day on the full span ($p = 0.73$); against the hybrid, $p = 0.24$ and $0.91$. No comparison rejects the null at the 5\,\% level, which is the expected outcome for 39 trades across two months; the equity series carry flat weekend samples, so the sixty daily observations overstate the effective count. The reading of Chapter~\ref{cap:conclusion} therefore stands. With February 2017 collected, a full trading year was registered on September 28, 2026, before any of its cells ran: the same one-year models unchanged, one \$10,000 account per cell from March 1, 2016 to February 28, 2017, ten cells (price-only, hybrid, news-only and both rule signs, at H1 and H4), March--October 2016 as development data and November 2016 to February 2017 as the untouched months, with hybrid against price-only at H1 as the primary paired comparison (block length 4, sensitivity 2) and the news arms secondary. Its outcome is reported in Section~\ref{subsec:trading-year}.

\section{Adaptive Retraining: The Frozen Policy Over the Registered Year} \label{sec:adaptive-retraining-results}

Both this section and Section~\ref{sec:candlestick-screening} report results at the H1 (sixty-minute) decision cadence rather than the M1 cadence used throughout Sections~\ref{sec:baseline-results}--\ref{subsec:session-2}. The departure is deliberate and disclosed, not a silent substitution: technical-debt item TD-71 (\path{algo-suite/docs/technical-debt.md}) records that LEAN's same-bar stop/target double-fill defect, already responsible for the sub-hour failures of Section~\ref{subsec:session-2}, corrupts M1-cadence runs specifically over this exact registered window (March 1, 2016 to February 28, 2017), so H1 sidesteps a known executor limitation rather than changing the experiment's clock for its own sake.

The first of the four December-extension follow-ups (Section~\ref{subsec:future-registered} of Chapter~\ref{cap:conclusion}) registered five retraining policies -- frozen (F), thresholds refreshed (Q), rolling (R), expanding (U) and exponentially weighted (E) -- on one continuous account, with prediction quality per epoch as an endpoint next to the paired daily-equity test. Of the five, only Policy F has since completed a run over the full registered year; refreshed-threshold, rolling, expanding and exponentially weighted comparisons remain outstanding, and no ranking across the five policies is reported here.

A narrower, earlier check bears on why the frozen policy was the one completed first. Distinct from the three-month offline refit already noted in Chapter~\ref{cap:conclusion}, a second offline trial (evidence \path{algo-suite/docs/stories/in-progress/19-adaptive-recency-retraining/evidence/d60-trial-results.md}) refit the H1 and H4 price-only family models monthly on a trailing 60-day window and chained the resulting months across the same one-year span: the 60-day policy did not beat a frozen comparator at either clock ($-45.4\,\%$ against $-51.3\,\%$ at H1, $-12.3\,\%$ against $-4.3\,\%$ at H4, over the same span), and the paired daily-return difference on the untouched months does not reject the null at either clock ($p=0.725$ at H1, $p=0.327$ at H4). This 60-day arm is kept in the study as the short-window control rather than as a candidate; it establishes only that the shortest of the five registered windows does not beat the frozen model, not that no adaptive policy can.

Table~\ref{tab:policy-f-year} reports Policy F's own registered-year backtest: the family and combiner models fitted once at $D_0=$ March 1, 2016 (spans of 311,737 fitting rows, 29,825 combiner-calibration rows and 28,801 threshold rows, all well above the registered minima) and never refit, run as the baseline chain from a single \$10,000 account over the full March 1, 2016--February 28, 2017 window. The fourth of the four December-extension follow-ups (Section~\ref{subsec:future-registered} of Chapter~\ref{cap:conclusion}) combined two distinct extensions under one heading: a contest of price-action, momentum and Ichimoku filters, and the fuller candlestick catalogue with its context rules rather than the six TA-Lib patterns used through Section~\ref{subsec:session-2}. Of these, only the candlestick-catalogue extension (Story 22) has run; the momentum/Ichimoku contest and the support-and-resistance location-and-target extension remain future work. Story 22, later extended by Story 23 with the Counterattack Line pair and Rising Three Methods, expands F3's catalog from the six patterns of Table~\ref{tab:intermediate-filter-parameters} (bullish and bearish engulfing, hammer, morning star, evening star, shooting star) to 22 admitted patterns, still built on the Nison/TA-Lib and Bulkowski catalogs of Section~\ref{subsec:pattern-features}, and adds a \path{pattern.enabled_rules} configuration key that restricts the catalog to a named subset for controlled experiments. \subsection{Whole-catalog backtest} \label{subsec:candles-whole-catalog}

With all 22 admitted patterns active together (strategy \path{candles-expanded-h1}, F3 in \path{required_entry} mode as the terminal filter, no F7 meta-learner), the catalog closed 285 trades over the registered year for a total return of $-32.79\%$, a Sharpe ratio of $-0.7851$, a maximum drawdown of 42.6\%, and equity of \$6,719.60 from a \$10,000 start. The identical configuration at \path{candles-expanded}'s own M1 default was also attempted over this window and refused at the statement step on TD-71 (a same-bar stop/target double fill); the same M1 configuration completed cleanly over full-year 2015, a window TD-71 does not affect, closing 1,810 trades for a $-99.54\%$ return -- consistent with, and no better than, the H1 result reported here.

\subsection{Combined-winners test} \label{subsec:candles-combined-winners}

The top five patterns by net profit or loss, with the five identical-signal ids of Table~\ref{tab:candles-per-pattern} collapsed to a single slot first since they are one shared signal rather than five independent ones, are \path{hanging_man}, \path{dark_cloud_cover}, \path{bearish_engulfing}, \path{evening_star} and \path{bearish_counterattack_line} -- all five bearish-polarity, an observation rather than a design choice. Enabling all five together, requiring exactly one eligible direction, closes 80 trades at a 31.3\% win rate for a net profit or loss of $-\$429.99$. This does not beat \path{hanging_man} alone ($+\$478.43$ on 38 trades): combining the individually least-bad patterns produced a worse result than the single best one. It does, however, beat the naive sum of the five patterns' solo results ($-\$2{,}767.58$), because the combined chain's shared eligibility requirement collapses bars where more than one of the five would have fired into a single trade rather than five separate ones (80 realized trades against 242 in the naive sum), not because the combination compounds each pattern's edge.

\subsection{Market-context diagnostics across the pooled sweep} \label{subsec:candles-context-diagnostics}

Pooling all 1,026 closed trades from the 22 individual pattern runs (the combined-winners run is excluded, since this diagnostic concerns the market context at entry, independent of any specific combination; F5 risk-guard and F6 capital-management fields are excluded throughout as position-sizing mechanics rather than market signal), four readings of F1's trend context at the entry bar were checked against trade outcome.

First, with-trend against against-trend: trades whose direction matched F1's plain EMA-based \path{trend_direction} at entry won less often (843 trades, 25.9\%) than trades against it (183 trades, 34.4\%). This is the opposite of the standard trade-with-the-trend heuristic, and it holds at the full pooled scale rather than only within individual patterns' much smaller subsets, so it is reported as a real, counter-intuitive finding rather than dismissed as a small-sample artifact.

Second, the higher-timeframe trend direction is structurally non-discriminating: it agrees with the base \path{trend_direction} in every one of the 1,026 completed trades, because F1 vetoes any bar where the two disagree before a trade can be opened, so no completed trade can ever carry a disagreement. This is reported as not measurable, rather than as no effect, since the null is architectural rather than empirical.

Third, trend strength in terciles shows no real separation: 22.2\%, 34.2\% and 25.8\% win rate low to high, non-monotonic.

Fourth, a composite trend score (signed \path{trend_direction} times \path{trend_strength}) shows a real, modest, monotonic effect across terciles: 24.8\%, 27.2\% and 30.4\%. Its sign already partly encodes trade direction, so this may reflect a directional bias specific to this one-year EUR/USD window rather than a universal trend-alignment effect, and it is reported with that caveat.

\subsection{A multiple-comparisons check on the screen} \label{subsec:candles-multiple-comparisons}

Twenty-two independent patterns were screened in Section~\ref{subsec:candles-per-pattern} and exactly one, \path{hanging_man}, showed a net-positive result. A permutation test (evidence and script \path{algo-suite/docs/stories/in-progress/22-candlestick-context-extension/evidence/multiple-comparisons-permutation-test.md}, seed 20260928) addresses whether this is more than the number expected by chance: the 1,026 pooled trades of Section~\ref{subsec:candles-context-diagnostics} were repeatedly reshuffled and re-partitioned, 20,000 times, into 22 groups of the same sizes as the real patterns, and the best (maximum) group total in each reshuffled trial was compared against the observed best, \path{hanging_man}'s $+\$478.43$. In 98.7\% of the 20,000 reshuffles (19,741 of 20,000), the best-of-22 result was at least as good as the one actually observed. \path{hanging_man}'s apparent edge is therefore not distinguishable from chance: finding one positive result out of 22 independent screens is, given this trade population's characteristics (a pooled mean of $-\$31.79$ per trade across all 1,026 trades), an unremarkable outcome rather than a surprising one. The screening process identified no pattern whose performance is statistically distinguishable from noise; \path{hanging_man}'s result is reported as a screening artifact consistent with the multiple-comparisons null, not as a discovered trading edge.

\subsection{News and candlestick combination} \label{subsec:news-candlestick-combination}

The combination of price-action patterns with news context tests this thesis's original central hypothesis directly. Two variants were run with \path{hanging_man} as the base pattern and F4 added to the chain.

First, with F4 present informationally only, never vetoing: 38 trades at $+\$478.43$, byte-for-byte identical to the pattern alone, trade for trade. F4 never once vetoed on any of \path{hanging_man}'s 38 eligible bars this year, so this is a genuine no-op, not a subtle null result.

Second, with F4 required to agree with the pattern (a real agreement gate): zero trades. This was investigated rather than only reported: on every one of the 35 bars where \path{hanging_man} was individually eligible, F4's own recommendation was ABSTAIN, because GDELT-derived sentiment for EUR/USD never once cleared its 0.15 threshold at the same time \path{hanging_man}'s own conditions were met. The two signals did not conflict; they simply never coincided over this entire year, so the null result here concerns the temporal non-coincidence of the two signal sources in this specific dataset, not an active disagreement between them.

In Wellington's own words, ``in the end, the news did not have a strong influence on the trades directly'' -- under this specific implementation and these specific, uncalibrated placeholder thresholds. This is a scoped finding about this GDELT feature build, this window and these thresholds, not a general claim that news-based features have no value in principle: the thresholds were never calibrated for this window, and a properly calibrated or differently-thresholded news signal might behave differently.

\section{Comparison with Closest Prior Art} \label{sec:zhang-comparison}

Section~\ref{sec:positioning} of Chapter~\ref{cap:methodology} named \citeonline{zhang2025macroalpha} as the closest published benchmark and reported its cost-adjusted Sharpe ratios of 5.87 on EUR/USD and 4.65 on USD/JPY under five-fold expanding-window cross-validation on daily features. A deflated Sharpe ratio for the present hybrid, computed with the schema-v2 procedure of Section~\ref{subsec:rule-significance} against the plausibility band that figure implies, is not reported here: no run in this chapter has a Sharpe ratio, plain or deflated, computed on its daily equity series, and assembling one honestly would require registering the block length and trial count over the full exploratory history built up across Sections~\ref{sec:ablations}--\ref{subsec:session-2} (the gate decision, both threshold grids, nine M1 sweep variants, fifty-one H4/H1/M15 tuning variants, the December extension, the news-only and rule cells, and the session-2 reproduction), which has not been done. This is a disclosed limitation, not an oversight: a single Sharpe-ratio confrontation against \citeonline{zhang2025macroalpha}'s figure would in any case compare a five-fold expanding-window daily-feature validation against this chapter's single pre-registered chronological split, so the two protocols are not read on the same axis even where both quantities exist.

What this chapter does supply, on the metrics it actually reports (win rate, maximum drawdown, net profit or loss, and paired stationary-bootstrap $p$-values on daily return differences), is a considerably more conservative reading than \citeonline{zhang2025macroalpha}'s headline figures. Every pre-registered comparison between the hybrid and the price-only baseline on an untouched window fails to reject the null: $p=0.15$ for the one-year protocol at H1 (Section~\ref{subsec:trading-year}), $p=0.77$ at H4, and $p=0.81$ and $p=0.29$ for the session-2 both-sides reproduction at 10\,\% and 5\,\% thresholds (Section~\ref{subsec:session-2}). The one configuration that clears the deposit over the full trading year, the reversed-sign news-only rule, was subsequently shown against its own always-short control to be statistically indistinguishable from the euro's realized drift over the window ($p=0.92$ at H1, $p=0.92$ at H4), not a demonstrated edge. None of this is comparable in magnitude to a Sharpe ratio above four; it is also a different question, since \citeonline{zhang2025macroalpha} reports an in-protocol cross-validation figure rather than a disclosed post-registration test against a drift control.

The two local points of prior art already cited in Chapter~\ref{cap:methodology} and Chapter~\ref{cap:introduction} bear more directly on this specific finding than \citeonline{zhang2025macroalpha} does, because both were produced in the same MBA programme on adjacent questions. \citeonline{vanhelden2021fx} reports that a macro-fundamental-plus-technical hybrid, built on the same combination logic across twelve pairs, earns a Sharpe ratio of 1.09 to 2.90 on six emerging Latin-American pairs but only 0.24 on EUR/USD and $-1.08$ on USD/JPY against the six developed-market pairs in that sample (Table~6, p.~35) --- precisely the two pairs the present work targets. The present chapter's null result for a differently sourced auxiliary channel (discrete GDELT event records rather than macro-fundamental indicators) on the same developed pair is consistent with that earlier finding rather than contradicting it: both pieces of local evidence point toward developed-market EUR/USD being harder for an auxiliary signal to improve than the emerging-market pairs where such gains have been documented. \citeonline{felix2024swing} identified, in the same programme, that textual information from news articles and analyst reports is acknowledged as a relevant qualitative input but was left unimplemented in that swing-trading study; the present work implements an event-derived (not full-text) auxiliary channel for a different asset class and a different clock, and the answer this chapter gives to the kind of gap Felix flagged is empirically negative within the window and instrument tested here, for the reasons disclosed in Section~\ref{sec:coverage-results} and Section~\ref{sec:experimental-threats}.

\section{Threats to Validity Specific to the Observed Results} \label{sec:experimental-threats}

The present evidence supports an implementation and execution report. It does not establish H1. A short single-pair window, overlapping labels, and daily event values repeated across minute rows limit generalization and invalidate treating row count as an independent sample size. Text sentiment is missing throughout; pattern detection is absent from the predecessor pilot but is observed in the new TA-Lib H4 cells.

Repeated inspection of September, gate changes, threshold grids, execution changes, nine named M1 sweep variants, fifty-one later H4/H1/M15 tuning variants and about thirty further exploratory cells create multiple exploratory selection opportunities. Selecting the least negative or zero-trade run would not turn this development window into an out-of-sample confirmatory test. The observed losses and F7/regime anti-alignment must be retained alongside favorable historical numbers. The full search history, rather than only the two finally reported strategies, is required for any selection adjustment; the 64 grid entries alone are not an established effective trial count for DSR. Recorded configuration values do not prove effective enforcement, and a successful manifest does not close this economic-validation gap. The candlestick screen of Section~\ref{sec:candlestick-screening} corrects for its own primary selection (22 independently tested patterns) with the permutation test of Section~\ref{subsec:candles-multiple-comparisons}, but the four gates and the ungated-momentum variant subsequently tested only on that screen's single positive pattern (Section~\ref{subsec:candles-gated-hanging-man}) are a further, uncorrected selection step layered on top of that correction; every gate result was negative, so this second step did not manufacture an apparent edge here, but it is the same kind of exploratory-selection opportunity flagged above and is not covered by the permutation test's accounting.

Four threats arise from what was observed. First, the gate decision was taken after inspecting September's zero-trade outcome, so September 2015 is development data for the ungated rule and cannot serve as its confirmation window; the threshold choice, by contrast, read only July and August. Second, the execution assumptions are unrealistic in a direction that flatters minute-scale flipping: a median spread of 0.3 pip as the only cost, zero fees, no enforced stop or take-profit, and a fixed half-of-equity notional in place of the F6 risk-based lot. Roughly one thousand trades per month with average wins and losses of a few hundredths of a percent would be dominated by any commission or slippage, so the signs of the September returns carry no economic information. Third, the F6 sizing was computed but not applied, so the capital-management layer described in Section~\ref{sec:execution-engine} has not been exercised, and the risk figures in Table~\ref{tab:pilot-parameters} describe configuration, not behavior. Fourth, F4 abstained on every bar, so the hybrid-minus-baseline difference measures only the news family's input to the combiner; it says nothing about the event gate, and a paired difference in a later window would still represent the joint effect of both unless the ablations of Section~\ref{sec:ablations} separate them.

The next-day event lag does not remove the documented late-reporting leakage from aggregation by event date. Fixed stop, pip-value, margin, and risk proxies require economic validation. Finally, schema-v2 inference in Section~\ref{subsec:rule-significance} requires complete daily equity, documented cost treatment and actual selection history, and that history must now record the gate decision and the sixteen-cell threshold grid per model. Legacy DSR adjustments and pooled-trade permutation outputs remain exploratory. An unavailable corrected statistic cannot be replaced with a legacy value. Subsequent runs must update this assessment with reconciled coverage, realistic execution costs, applied risk sizing, and paired uncertainty computed on a window that no decision in this chapter has touched.
